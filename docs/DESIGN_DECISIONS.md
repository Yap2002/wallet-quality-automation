# 五个关键设计取舍

1. MySQL是真实来源，Redis只做可选状态缓存。优点是Redis丢数据或宕机不影响资金正确性；代价是数据库仍承担核心查询和锁压力。
2. 钱包余额快照加双重记账。快照查询快，分录可审计；代价是每次资金动作必须原子更新两类数据并持续做一致性检查。
3. 幂等键持久化失败结果。同键重试获得稳定语义；代价是需要保存错误信息、请求指纹和清理策略，不能只做一个唯一键。
4. 退款新增反向交易，不修改原分录。审计历史完整且容易证明资金流；代价是查询净额时需要聚合原交易和退款。
5. API用Requests，进程内集成用HTTPX，UI用Playwright。每个工具验证不同层；代价是工具数量增加，因此公共数据和断言必须集中，避免三套重复业务逻辑。

规模增大后的演进：账务分区与归档、Outbox消息、回调队列、读写分离、对账任务、分布式追踪、基于版本号的乐观锁、缓存命中率和延迟监控。Redis仍不能成为资金最终事实来源。
