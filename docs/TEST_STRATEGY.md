# 测试策略

风险优先级：资金重复影响、负余额和账务不平衡为P0；幂等冲突、退款超额、回调乱序和权限为P1；页面展示和报告体验为P2。

测试金字塔：纯Money、FeePolicy和状态机使用快速单元测试；API与真实MySQL使用集成测试；Requests、Newman和Playwright覆盖黑盒链路；Hypothesis验证通用性质；线程并发验证锁与事务；Locust/JMeter验证性能脚本和基线。

并发事务策略：并发测试必须连接真实MySQL，不能用SQLite或Mock数据库代替。典型场景以余额100元同时发起10笔30元提现，预期只有3笔成功、7笔余额不足、最终余额10元；除状态码外，还要确认只新增3条成功交易，且每条交易的借方等于贷方。转账按钱包ID固定顺序加锁，降低相向转账死锁风险。

资金一致性策略：断言按“HTTP响应→交易状态→钱包余额→账务分录→系统不变量”逐层收紧。事务保证一次请求中的余额、交易和分录全部提交或全部回滚；幂等保证同一业务请求重试不会再次产生资金影响，两者不能混为一谈。

断言分层：HTTP状态码只证明协议结果；业务code证明错误分类；响应字段证明接口契约；SQL余额和交易证明持久化；账务分录证明资金守恒；日志trace ID证明可定位。资金场景不能只断言HTTP 201。

数据策略：每条用例使用UUID或运行ID创建独立用户；Factory记录邮箱并精确清理；DatabaseClient拒绝清理非`_test`数据库；并行用例不共享固定用户；Postman、JMeter和Locust使用专属前缀并在finally清理。

异步策略：状态轮询使用单调时钟、短间隔和总超时；成功立即返回；超时错误包含最后状态。禁止固定sleep后假设完成。

性能策略：JMeter用于固定链路、变量提取、响应断言和持续时间断言；Locust按4:1权重模拟余额查询与充值混合负载。性能结论必须记录并发用户、启动速率、持续时间、样本数、错误率、P95和RPS。Locust门禁默认要求错误率不高于1%、P95不高于500ms、吞吐不低于1RPS，阈值可通过环境变量调整；这些宽松默认值只验证流水线和脚本，不代表生产SLA。

CI/CD门禁：push和Pull Request运行Alembic、Ruff、格式检查、mypy、接口与资金回归、独立并发事务门禁、UI Smoke和Allure归档；Locust性能基线使用定时或人工工作流，避免短时性能波动阻塞每次代码提交。Jenkins与GitHub Actions调用同一套测试入口，不复制业务测试逻辑。
